## Problem / Context

- The viewer renders its `dxdiff` classes and ships no colors at all, so a mounted viewer is an unstyled table.
- The reference carries its light and dark palettes in emotion style objects a consumer replaces per instance, and Rust has no counterpart to that shape.
- What a consumer may override, and how their own rules reach the viewer, is the contract this unit settles in CSS rather than in a Rust API.

## Plan / Guidance

- One stylesheet the crate embeds and the component renders into the document, inside a cascade layer, so an app's own rules take effect at any specificity.
- Palette defaults are declared at the document root, so an app's assignment on an ancestor reaches a viewer following the reader's preference; a viewer given an explicit theme may carry that theme's values on its own element, where app rules reach the viewer element or below.
- Overriding one mounted viewer is ordinary CSS against the `dxdiff` classes and the `--dxdiff-` names; the crate adds no Rust type for it.
- Colors come from the reference palettes; what else the sheet carries is what the viewer needs to read as the reference does. Where the markup leaves no way to read a reference color, the markup is what changes, which is why this unit marks the clickable gutter.
- The design is settled and recorded in the architecture this unit references; hold it as a constraint rather than a starting point.
