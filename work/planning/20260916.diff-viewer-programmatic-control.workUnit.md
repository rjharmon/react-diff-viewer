## Problem / Context

- Apps may want to drive a mounted diff viewer from their own code: read where the changes are, read which lines are folded, and steer folding, not only reset it.
- The reference offers nothing like this: its only outward surface is props in, a line-number click out, and one reset method.
- The component unit keeps its crate-owned handle to reset alone; this unit widens what that handle exposes.

## Plan / Guidance

- Change and fold positions come from data the engine and component already compute; the engine returns positions, not runs, so runs are derived.
- Keep the component unit's rule: an app never names a fold. Reading is safe; steering takes app-shaped requests in line numbers, which the crate maps onto its own folds.
- Once the handle reads state, it is a control rather than a trigger, and its name changes with it.
- Risk signals: architectural-uncertainty, since both the read surface and the steering form are unsettled.
